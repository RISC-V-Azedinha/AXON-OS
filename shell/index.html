    Shell¶

    Assim que o AXON-OS termina o boot, a tarefa Task Shell assume a UART e apresenta um prompt interativo:

    root@axon:~$

    O shell roda como uma tarefa comum do escalonador (prioridade 2) — ele não é um caso especial do kernel. Ele lê caracteres de um buffer circular alimentado pela interrupção da UART (veja Interrupções e chamadas de sistema), monta uma linha de comando e despacha para a função correspondente em uma tabela estática de comandos.

    Teclas especiais¶

    Tecla Efeito
    Enter Executa o comando digitado
    Backspace Apaga o último caractere
    Ctrl+L Limpa a tela e redesenha a linha atual

    Sintaxe de comandos¶

    <comando> [argumentos]

    O shell separa o comando dos argumentos no primeiro espaço encontrado — não há suporte a aspas, múltiplos espaços ou pipes. Se o comando digitado não existir na tabela, o shell responde com Unknown command: <nome>.

    O editor edit¶

    edit <arquivo> abre um mini-editor de texto no estilo nano, implementado inteiramente dentro do comando de shell (sem processos separados — é só um laço de leitura de teclado dentro da própria tarefa do shell):

    edit notas.txt
    • O conteúdo do arquivo é lido para um buffer de 2 KB em RAM.
    • Digitação normal insere caracteres no fim do buffer (não há um cursor navegável — é um editor de "acrescentar/apagar no final", como um tail editável).
    • Ctrl+W salva o buffer de volta no arquivo (via a mesma syscall usada pelo comando write).
    • Ctrl+X sai do editor e retorna ao prompt do shell.
    • Backspace remove o último caractere; se o caractere removido for uma quebra de linha, a tela inteira é redesenhada (o editor não mantém um modelo de cursor 2D, então a forma mais simples e segura de refletir a mudança é redesenhar).

    Enquanto o editor está ativo, a variável global g_editor_mode fica em 1, o que pausa a atualização do relógio de uptime no canto da tela (feita pela Task Monitor) para não conflitar com o redesenho do editor.

    Exemplo de sessão¶

    root@axon:~$ touch notas.txt
File created.
root@axon:~$ edit notas.txt

     AXON NANO    File: notas.txt
 [Ctrl+W] Save   [Ctrl+X] Quit
------------------------------------------------

    root@axon:~$ cat notas.txt
Minha primeira anotação no AXON-OS!
root@axon:~$ ls

  FILES:
  -------------------
  notas.txt

    Acesso concorrente à UART¶

    Como três tarefas escrevem na mesma UART (Task Shell, Task Monitor e Task LEDs), todas usam safe_puts()/sys_puts() protegidos por um mutex compartilhado (uart_mutex), evitando que a saída de uma tarefa se intercale no meio da saída de outra. Veja Tarefas e escalonamento para os detalhes do mecanismo de exclusão mútua.

    Referência de comandos¶

    Todos os comandos registrados em shell_commands[] (src/apps/task_shell.c).

    Sistema¶

    help¶

    Lista todos os comandos disponíveis, com uma breve descrição de cada um.

    help

    clear¶

    Limpa a tela e reimprime o cabeçalho do AXON-OS.

    clear

    reboot¶

    Reinicia o sistema imediatamente (aguarda 500 ms e salta de volta para _start()).

    reboot

    panic¶

    Dispara deliberadamente uma exceção de instrução ilegal (.word 0xFFFFFFFF), para exercitar o caminho de tratamento de crash do kernel (veja Interrupções e chamadas de sistema → Exceções não tratadas). O sistema reinicia automaticamente 3 segundos depois.

    panic

    Processos¶

    ps¶

    Lista todas as tarefas do sistema: PID, nome, prioridade, estado, stack pointer atual e (se bloqueada) o ciclo de despertar.

    ps

      PID   NAME            PRIO   STATE         SP          WAKE_TIME
  --------------------------------------------------------------------
  0     Task LEDs       1      READY         0x8003FC80  -
  1     Task Monitor    1      RUNNING       0x8003F880  -
  2     Task Shell      2      READY         0x8003F480  -
  3     Idle            0      READY         0x8003F080  -

    stop <pid>¶

    Suspende a tarefa com o PID informado (SYS_SUSPEND). A tarefa Idle (prioridade 0) não pode ser suspensa.

    stop 0

    resume <pid>¶

    Retoma uma tarefa previamente suspensa (SYS_RESUME).

    resume 0

    Memória¶

    heap¶

    Imprime o mapa completo do heap: endereço de cada bloco, tamanho, status (FREE/USED) e resultado da checagem de integridade do canary.

    heap

    alloc <bytes>¶

    Aloca um bloco de bytes bytes no heap do kernel via sys_malloc e imprime o endereço retornado — pensado para ser usado em conjunto com poke, como uma forma "segura" de uma tarefa reservar memória própria antes de escrever nela.

    alloc 128

    free <addr>¶

    Libera o bloco alocado no endereço hexadecimal informado.

    free 0x8003a010

    defrag¶

    Solicita a fusão (coalescing) de blocos livres adjacentes no heap.

    defrag

    peek <addr>¶

    Lê 32 bits do endereço físico informado (hexadecimal, com ou sem prefixo 0x).

    peek 0x10000000

    poke <addr> <val>¶

    Escreve 32 bits (val) no endereço físico informado (addr).

    poke 0x20000000 0xFF

    Sem verificação de limites

    peek/poke acessam memória física diretamente, sem nenhuma validação — é possível corromper o próprio kernel escrevendo em um endereço errado. Use com cuidado.

    memtest¶

    Teste simples de alocação: aloca 128 bytes com kmalloc, imprime o endereço e libera em seguida.

    memtest

    Sistema de arquivos¶

    ls¶

    Lista os arquivos existentes no RamFS.

    ls

    touch <arquivo>¶

    Cria um arquivo vazio.

    touch notas.txt

    rm <arquivo>¶

    Remove um arquivo.

    rm notas.txt

    cat <arquivo>¶

    Imprime o conteúdo de um arquivo na tela.

    cat notas.txt

    write <arquivo> <dados>¶

    Escreve texto simples em um arquivo, sobrescrevendo o conteúdo anterior. Tudo depois do primeiro espaço é tratado como o conteúdo a ser gravado (sem suporte a aspas).

    write notas.txt Ola Mundo

    edit <arquivo>¶

    Abre o mini-editor de texto embutido (Ctrl+W salva, Ctrl+X sai).

    edit notas.txt

    GPIO¶

    Só na FPGA (no QEMU os comandos funcionam sobre um estado virtual). Portas: ja, jb, jc, jd (Pmods, 8 pinos), led (LD0..LD15), sw (chaves) e btn (bit 0 = BTNU, 1 = BTND, 2 = BTNL, 3 = BTNR). Nos Pmods, o pino i é o pino i do conector na ordem 1, 2, 3, 4, 7, 8, 9, 10.

    gpio [<porta> [<pino> [in|out|0|1|t]]]¶

    Sem argumentos, lista a direção e a entrada de todas as portas. Com a porta, mostra só ela; com o pino, lê o pino; com uma ação, configura a direção (in/out), escreve (0/1) ou inverte (t) o pino.

    gpio
gpio ja 0 out
gpio ja 0 1
gpio sw 3

    seg <valor>¶

    Mostra um número nos displays de 7 segmentos: decimal (seg 1234), hexadecimal (seg x1F) ou apaga (seg off).

    rgb <0|1> <r> <g> <b>¶

    Acende o LED RGB LD16 (0) ou LD17 (1) com o brilho 0..255 de cada cor (255 é 1/8 do LED ligado direto).

    rgb 0 0 255 0
